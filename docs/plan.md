## Этап 1 · Конспекты и протоколы из записей лекций

### 1.1 · Обосновать или пересмотреть модель распознавания речи — готово

Исходная проблема: faster-whisper large-v3 был выбран на прошлой неделе
сравнением с turbo на одном файле, без эталона, на глаз. Хуже того,
«~91.5 % совпадения» считалось **между двумя расшифровками** — это
похожесть, а не точность; две модели одного семейства ошибаются одинаково.
Единственное, что было измерено честно — время (22.9 с против 10.5 с), и
это ровно та величина, которая здесь не решает: шестнадцать минут
расшифровываются за двадцать три секунды, расшифровка идёт один раз после
лекции.

**Что решено.**

Кандидаты, три:
* `Systran/faster-whisper-large-v3` — действующий, иначе не с чем сравнивать
* `mobiuslabsgmbh/faster-whisper-large-v3-turbo` — соперник, отвергнутый без оснований
* `nemo-parakeet-tdt-0.6b-v3` — другое семейство (transducer, не генеративный
  декодер), физически не может выдумать текст из тишины; украинский заявлен,
  WER 6.79 % Fleurs / 5.10 % CoVoST, пунктуация и регистр есть

`w2v-bert-uk v2.1` (6.6 % WER на Common Voice 10) в тройку не взят: не даёт
пунктуации и регистра, сравнивать по WER нечестно, и протокол из стены слов
собирать хуже. Может пойти отдельной строкой позже.

Canary 1B v2 отвергнут: крупнее, требует 6 ГБ вместо 2, а числа по
украинскому отдельно не опубликованы, только агрегат по 25 языкам.

**Эталон.** Консенсус четырёх: три кандидата плюс Gemini как четвёртый
транскрибатор по аудио. Gemini именно транскрибатор, не судья — объявить её
истиной значит померить «похожесть на Gemini» и повторить ту же ошибку с
другим якорем. Текстовая модель судьёй быть не может вовсе: не слышала
аудио, выберет то, что глаже, а глаже всегда Whisper, потому что он
причёсывает.

Работает так: выравниваем четыре расшифровки, смотрим только позиции, где
они разошлись, эти места он разбирает на слух. Согласие ожидается процентов
девяносто, значит слушать придётся десятую часть — около двадцати пяти минут.
Плюс минута, расшифрованная вслепую с нуля, — она меряет то, что промахнули
все четверо, единственную величину, которую консенсус о себе знать не может.

Честная слабость метода: общая ошибка всех участников остаётся невидимой,
абсолютный WER будет занижен. Но эта ошибка одна и та же для всех, то есть
добавляет общую константу и на ранжирование не влияет. Для абсолютной оценки
метод не годится, для сравнения трёх — годится.

**Соглашения расшифровки — не зафиксированы, это ближайший шаг.** Эталон это
не «правда», а набор соглашений: пишем ли «ну» и «тобто», оставляем ли
оборванные фразы, «сімдесят балів» или «70 балів». Каждое решение двигает WER
на проценты и притом в пользу конкретного семейства: Whisper нормализует и
выбрасывает мусорные слова, transducer-модели транскрибируют буквальнее.
Без письменно зафиксированных соглашений сравнение нечестное.

**Вторая метрика — постоянство терминов.** Считается по выводам моделей
**без эталона вообще**: сколькими разными способами модель записала один и
тот же термин. Для нашей трубы она важнее WER: WER накажет одинаково за «ну»
и за термин, а разнобой в терминах ломает следующий этап структурно — RAG
нарежет «IDS» и «ай-ді-ес» в разные чанки и не свяжет их.

Поэтому порядок перевёрнут: сначала бесплатное (прогон + постоянство), потом
по результату решаем, где тратить его двадцать пять минут.

**Что уже видно в готовой расшифровке large-v3, до всяких прогонов:**
* `action item` → трижды «екшн-айтеми», один раз `action item`
* `continue` → «контінію» четырежды и «контін'ю» один раз
* `good`/`bad` → дважды латиницей, один раз «бед»
* `peer review` → «пір-рев'ю» и «перерев'юю»
* `ретроспектива` → один раз «ретро-перспективи»

Оговорка: часть разнобоя может быть честной — лектор мог правда сказать один
раз по-английски. Проверяется только эталоном. Но «ретро-перспектива»,
«перерев'юю» и апостроф в «контін'ю» произнести нельзя: это ошибки, не речь.

**Правило вместо словаря** (2026-09-23, принято как гипотеза под проверку).
Словарь замен вариантов — грабли: каждая дисциплина и каждый рабочий проект
требуют свой, а случайные искажения в него не впишешь никогда. Глоссария
извне тоже нет: в силлабусе его нет, а рабочие записи с учебными
материалами не связаны вовсе. Поэтому цель написания задаётся правилом, не
списком: **английские заимствования — в оригинале, латиницей**. Правило
от предметной области не зависит.

Кто применяет:
* Whisper — через `initial_prompt` как образец стиля, не глоссарий: одна
  нейтральная фраза со смешанным письмом, без предметных слов, одна и та же
  для лекций и работы. Декодер продолжает манеру подсказки. Риск: на тишине
  Whisper бывает дописывает текст подсказки, а VAD у нас выключен.
  У Parakeet такого рычага нет — это тоже результат.
* gemma4 в 1.3 — сводит варианты внутри документа к одному написанию по
  тому же правилу, без списка. Отдельно мерить, не «исправляет» ли верное.

Честная граница: термин, который модель не узнаёт как слово (узкий жаргон,
внутренние названия проектов), правилом не лечится. Для него — глоссарий,
который пополняется руками, как необязательная надстройка.

Следствия:
* Критерий 1.1 меняется: не «кто лучше слышит», а «кто лучше слышит и
  поддаётся правилу».
* Нормализатор для WER (словарь 18 терминов) — только инструмент этого
  замера, в продукт не идёт.
* Ограничение материала: в выборке нет рабочих записей. Переносить вывод
  1.1 на них без проверки нельзя.

### 1.2 · Служба транскрипции (`/api/live`, `/api/runs`) — **текущий**

**Назначение задано им** (2026-09-24): расшифровка идёт фоном с задержкой в
секунды, звук берётся только у приложения встречи (Meet, Zoom), а не у всей
системы; микрофон включается кнопкой и по умолчанию выключен, чтобы не мешать.

**Выбран один механизм захвата — процессный loopback.** Путей было три:
loopback устройства вывода (весь звук системы), процессный loopback
(`ActivateAudioInterfaceAsync` + `PROCESS_LOOPBACK`, Windows 10 2004+) и
расширение Chrome с `tabCapture`. Граница «только Мит, а не весь Хром»
процессным loopback не проводится: Хром сводит звук всех вкладок в дочернем
audio service, и дерево процессов браузера отдаёт их вместе. Принято как цена
на время; точность по вкладке — позже, третьим путём, в тот же интерфейс
источника.

**Реализация без компилятора** (`scripts/wasapi_loopback.py`). Visual Studio
на машине нет, поэтому COM вызывается из питона через `comtypes`; готовой
обёртки в питоне для процессного loopback не существует. Грабля, стоившая
первого прогона: объект обратного вызова обязан заявлять ещё и `IAgileObject`,
иначе API отвечает `E_ILLEGAL_METHOD_CALL` и не объясняет ничего.

**Что проверено измерением** (2026-09-24), тон-сигналы и запись лекции:
* изоляция: два процесса играют одновременно, в захвате целевого чужой тон
  −126 дБ, то есть его нет;
* `--exclude` на том же PID даёт тишину — обратная проверка той же изоляции;
* Хром: тон вкладки ловится через дерево процессов браузера, 523 Гц;
* время: 440 Гц → 3 с тишины → 880 Гц восстановлены с точностью до 0.3 с
  задержки старта, без сдвига после паузы;
* дрейф часов: −12 мс за 180 с, и ровно столько же на первой секунде, то есть
  постоянный сдвиг, а не уход. Таймкоды по счётчику сэмплов надёжны на лекцию;
* движок отдаёт сразу 16 кГц моно — своего ресемплера в коде нет.

**Опровергнутое допущение.** Ожидалось, что на тишине WASAPI не отдаёт пакетов
(как при loopback устройства) и ленту придётся достраивать нулями по часам.
Процессный loopback отдаёт нули сам: процесс молчал 10 с — пришло ровно 10 с
нулей. Достройка в коде осталась только для дырки при переподключении.

**Сквозной прогон** (`scripts/live-run.py`, 150 с, turbo, лекция играет во
вкладке Хрома): цикл 0.34 с (p90 0.52), задержка слова 2.14 с (p90 3.47,
худшая 5.63), захвачено ровно столько, сколько прошло по часам (−0.02 с).

WER того же отрезка против эталона 1.1:

| | WER |
|---|---|
| живой тракт (Хром → LocalAgreement) | 25.8 % |
| офлайн из записи захвата | 25.8 % |
| офлайн из оригинала (лучший случай) | 24.7 % |

То есть тракт стоит ≈1 п.п., а живой режим сверх него — ноль. Оговорка:
отрезок короткий (190 слов эталона) и плотный на одновременную речь, поэтому
абсолютные 25 % выше общелекционных 15.3 % у turbo и не сравнимы с ними.

Отдельно проверено, что расхождение текстов (82.6 % совпадения слов с
распознаванием оригинала) — это не потеря точности: сдвиг исходника на один
сэмпл даёт 94 %, ресемпл 16→48→16 кГц — 87.5 %, то есть модель сама
неустойчива, а тракт добавляет к этому немного. В настоящей встрече двойного
ресемпла не будет: звук приходит 48 кГц, а не 16.

**Микрофон** поднят на том же слое (`open_mic_stream`, автоконвертация в
16 кГц моно), по умолчанию выключен, вторая дорожка отдельным файлом — эхо
динамиков в общем сигнале ломало бы подтверждение LocalAgreement.

**Запись на диск** ведётся потоком, каталог — параметр (`--rec-dir`), по
умолчанию `data/audio/live/`. Имя — дата и время, без предмета и имён.

**Предохранитель на буфер — сделан и оказался бесплатным** (2026-09-24).
Обычная обрезка возможна только по концу сегмента, который уже весь
подтверждён; на речи без пауз резать не по чему, буфер растёт, а цикл растёт
вместе с ним, потому что каждый раз распознаётся весь буфер заново. Теперь
буфер длиннее `--max` режется принудительно по концу последнего
подтверждённого слова, а если подтверждённого в буфере нет вовсе (модель
встала — ровно тот случай, ради которого это и писалось), режется по живому,
и такой рез считается отдельно как шов.

Симуляция turbo, `--max 20` против прежнего «без предела»:

| | без предела | max 20 |
|---|---|---|
| WER | 16.77 % | 16.77 % |
| цикл p90 | 0.63 с | 0.47 с |
| буфер, наибольший | 31.1 с | 18.6 с |
| принудительных резов | — | 39 |
| швов по живому | — | 0 |

То есть за 16 минут лекции точка реза по подтверждённому слову находилась все
39 раз, резать по живому не пришлось ни разу. Точность не изменилась совсем,
цикл стал ровнее. В `live-run.py` и службе предел по умолчанию 30 с.

**Служба — сделана** (`scripts/live_service.py`, FastAPI, 127.0.0.1:8756).
Ядро цикла вынесено в `scripts/live_core.py`, поэтому CLI и служба — две
обёртки над одним кодом, а не две реализации. Сеанс один за раз: карта одна,
и модель делит её с gemma4. Модель остаётся в памяти между сеансами.

| | |
|---|---|
| `GET /api/targets` | что можно слушать: корневые процессы известных программ |
| `POST /api/live/start` | `{target\|pid, model, mic, chunk, trim, max_sec}` |
| `POST /api/live/stop` | останавливает и возвращает статистику сеанса |
| `GET /api/live` | состояние: PID, отставание, буфер, слова, швы |
| `GET /api/live/text` | текст текущего сеанса целиком |
| `GET /api/live/stream` | SSE: подтверждённые слова и события по мере появления |
| `GET /api/runs`, `/api/runs/{id}` | прошлые сеансы из `out/live/` |

Проверено вживую: список целей отдаёт Chrome, Discord, Edge с временем
запуска; SSE отдаёт состояние и держит соединение; сеанс на 20 с прицепился
к Chrome (PID 21636), записал дорожку и вернул полную статистику.

Замеченное на этой проверке: на тишине VAD не отдаёт сегментов, поэтому
буфер растёт и предохранитель однажды сработает вхолостую — счётчик швов в
этом случае считает не потерю. Не чинится до тех пор, пока не мешает.

**Микрофон** поднят вторым источником того же вида (`MicSource`), пишется

колонок у ПК нет, только наушники.

* Общий ноль: каждый источник помнит `perf_counter()` сэмпла 0. Сдвиг между
